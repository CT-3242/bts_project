DESCRIPTION

La mairie est une collectivité territoriale au cœur de l'administration publique. Contrairement au secteur privé, dont la finalité est lucrative, les missions de la mairie sont de proposer différents services de proximités pour les citoyens (état civil, urbanisme, écoles).

Jai effectué mon stage au sein du service DSIO (Direction des Systèmes d'Information et d'Organisation) Ce service est le pilier technologique de la collectivité. Ses missions sont

La gestion du parc informatique en assurant le déploiement, la maintenance et l'évolution des installations dans les différents services de la mairie et dans la ville.

Administrer et mettre à jour les sites web de la commune pour garantir l'accès à l'information et aux démarches administratives en ligne.

Accompagner les agents municipaux dans l'utilisation de technologies pour garantir la continuité du service public.

TECHNOLOGIES

Durant la période jai du développer en autonomie lapplication pour smartphone devant recevoir les notifications avec les informations concernant les incidents se passant dans la ville

Elle serait utilisé sur lOS ANDROID puis IOS

Le service ne possaidait pas dexpertise interne en développement dapplication pour smartphone, il était donc impossible de me faire aider. Je ne possédais pas de cahier des charges pour comprendre le contexte ou la liste de fonctionnalités Mon maitre de stage mavait expliquer les besoins de lapplication mais concevoir le projet de zero était bien plus difficile Le projet était de développer lapplication sous la technologie KOTLIN (utilisé pour le développement ANDROID) Elle devait vérifier lexistence du fichier contenant les informations de lincident avec son URL. Puis il devait créer la notification avec les informations. Pour développer cette application je passai à travers trois phases pour surmonter les contraintes techniques.

PREMIÈRE TENTATIVE

Je pensais pouvoir utiliser les méthodes de KOTLIN pour vérifier lexistence du lien avec la méthode HTTP HEAD tous les X secondes (POLLING) puis utiliser la méthode GET pour télécharger le fichier ou copier les données pour construire la notification avec lURL. Mais je me suis heurté aux sécurités de lOS (DOZE MODE). Ce mode restreint les communications extérieurs en plus de suspendre les processus en arrière- plan pour économiser les ressources et la batterie Aussi il était impossible de maintenir ce processus en permanence sans être bloqué Evidement vérifier lURL ne poserait pas de problème mais je ne pouvais passer outre cette sécurité

DEUXIÈME TENTATIVE

Ne pouvant pas utiliser lapplication pour vérifier lexistence du lien je devais impérativement changer de méthode comme créer le serveur pour le faire

Je décidai de créer le serveur avec NODEJS pour contourner le problème de vérification Je pensais pouvoir lutiliser pour vérifier le lien puis transmettre en HTTP les données (je devais aussi pouvoir transmettre le message pour les personnes pouvant être en extérieur) puis construire la notification dans lapplication Connaissant déjà la technologie il était plus aisé de développer les différentes parties Je maidai de différents sites de développement et de lIA pour créer les routes pour transférer les données en JSON [je tentai de créer le fichier A pour linstammer dans le smartphone mais le stage se terminant je ne pu vérifier son installation Cependnat je documentai sa création dans lIDE pour laisser les prochaines personnes continuer le développement]

TROISIÈME TENTATIVE

Pendant le développment du serveur je compris le fonctionnement de notification en utilisant la connexion du smartphone. Dans les circonstances habituelles chaque application devriat installer son composant pour relier leur serveur aux application mais cela nécessiterait constament de coonecter les projets comme avec les web socket

LIA maidait pour la création de notification. Les classes avec ses méthodes avaient changé, la documentation était obsolete et GOOGLE conseillait dutiliser leur IA pour développer les applications Je disposais de deux possibilités pour créer les notifications Créer la notification dans le smartphone avec les composants ANDROID ou Transferer les données contenu dans le serveur vers FCM (le serveur de notification) puis les transferer (de la "push notification") vers le smartphone. La solution forcait lutilisation de FCM Pourquoi Maintenir une connexion ouverte entre le serveur et les smartphnes viderait la batterie des utilisateurs Pour éviter cela le serveur FCM avec ses composants installé transférait les messages si il reçoit les données avec lidentifiant du smartphone Lapplication devait transférer son TOKEN au serveur pour pouvoir identifier les smartphones lors du transfert vers FCM

La dépendance de lapplication dans lutilisation de FCM pouvait poser problème pour les données transitant sur les serveurs de FIREBASE Le service ne pouvait pas avoir de controle Elles pourraient être stocké ou utilisé sans autorisation Comme lillustre le plan 4 FCM sert de pont basse consomation Il est indispensable pour assurer la liaison avec lOS Ironiquement je découvrais aussi le fonctionnement de route de requête HTTP de données en JSON plusieurs mois avant de le voir
